# 见岸（Jian'an）

> 面向强迫症（OCD）人群的微信小程序自助工具：AI 陪伴 + 症状记录 + 暴露练习。
> 以「识别 → 稳定 → 练习」为主线，把循证方法做成日常可执行的小步骤。

---

## 一、它解决什么问题

强迫症的日常困境不是「不知道道理」，而是**知道却停不下来**：反复检查、反复求证、被侵入性思维折磨。

市面上的心理类应用大多停在「聊聊天」或「记记心情」，缺少针对 OCD 的操作性工具。本项目试图把三件事接起来：

1. **分清楚**——这是强迫性的怀疑，还是普通的担心？（AI 对话 + 亚型识别）
2. **稳下来**——当下这一分钟能做什么？（仪式延迟、不确定性接纳、呼吸锚定）
3. **练起来**——把暴露与反应阻止（ERP）拆成可以自己走的台阶（恐惧阶梯 + SUDS 记录）

同时，产品对**共病**保持完整尊重：抑郁、焦虑、睡眠问题不会被当成「强迫症的附属品」一句话带过。

## 二、功能

| 模块         | 说明                                                                         |
| ------------ | ---------------------------------------------------------------------------- |
| AI 对话      | 三位人格（陪伴 / 科普 / 倾听），服务端持有全部提示词与安全规则，前端只传消息 |
| 安全分诊     | 四级分类 + 多路路由，区分真实危机、需要澄清、OCD 侵入性思维、普通对话        |
| 情绪标签     | 规则 + 模型双通道产出情绪标签，驱动前端表情状态，不额外增加一次调用          |
| OCD 专精路由 | 十类亚型识别、八类共病信号、P0–P4 优先级决策（含双主轴标记）                 |
| 自评量表     | 12 题 / 18 题两套，用户自选；**非诊断**，结果仅作参考                        |
| 恐惧阶梯     | 自定义暴露层级，记录每级目标 SUDS 与实际完成情况                             |
| 暴露练习     | 前测 → 计时 + 仪式阻断 → 后测 → 落库，形成进度曲线                           |
| 症状日志     | 记录念头、行为、抵抗情况、耗时；周统计与趋势                                 |
| 危机兜底     | 命中危机时直接返回固定文案 + 全国心理援助热线 12356 等渠道                   |

## 三、技术栈

- **前端**：微信小程序原生（WXML / WXSS / JS），无第三方 UI 框架
- **后端**：微信云开发（CloudBase）云函数，Node.js
- **数据库**：云开发文档型数据库，四个集合，全部经云函数访问
- **模型**：任意 OpenAI 兼容服务（默认 DeepSeek 官方），服务端代理，Key 不下发前端
- **测试**：Node.js 内置 `node --test`，无外部测试框架

## 六、快速开始

安装 Node.js 22/24（含 npm）、微信开发者工具，并准备自己的 AppID、云环境和 DeepSeek Key。

```bash
npm ci --ignore-scripts
npm run check
```

PowerShell 初始化配置：

```powershell
Copy-Item project.config.example.json project.config.json
Copy-Item .env.example .env
```

Bash 使用 `cp` 执行同样的复制。随后：

1. 设置 `project.config.json` 的 `appid`；**设置 `miniprogram/app.js` 的 `CLOUD_ENV` 为自己的云环境 ID**。
2. 开发者工具导入仓库根目录，选择该云环境，分别右键上传部署 chat 和 ocd（云端安装依赖）。
3. 在 chat 云端环境变量填写 Key 与开关；本地根目录 .env 不会自动上传。
4. 在控制台把两个函数超时至少设置为 60 秒；有重试/备用链路时仍需实测总耗时。
5. 创建四个集合并将客户端权限设为 `{"read": false, "write": false}`，再验证读写、分页和用户隔离。

完整步骤、CLI 部署、索引建议和上线验收见 [部署指南](docs/DEPLOYMENT.md)。
默认保留 DeepSeek 官方直连与原包模型代号；实际模型权限和云端运行时以部署账户实测为准。
`shadow` 用于观察，安全路由仍保留旧规则体验；完成验收后应明确选择是否启用 `on`。

## 七、环境变量

| 变量                                 | 必填 | 说明                                              |

| `DEEPSEEK_REASONING_EFFORT`          | 否   | `none` 关闭思考链（推荐），留空用服务端默认       |
| `SAFETY_ROUTER_V2_MODE`              | 否   | `off` / `shadow` / `on`                           |
| `EMOTION_LABEL_MODE`                 | 否   | `off` / `shadow` / `on`                           |
| `OCD_ROUTER_MODE`                    | 否   | `off` / `shadow` / `on`                           |
| `UNCERTAINTY_PAUSE_ENABLED`          | 否   | `0` 关闭，其他值开启                              |

## 八、核心机制

### 8.1 安全分诊：四级 + 多路

输入先过规则层，不依赖模型判断：

| 级别            | 含义                           | 处理                                  |
| --------------- | ------------------------------ | ------------------------------------- |
| `crisis`        | 自伤/自杀的明确意图或计划      | 固定文案 + 热线，不进入模型对话       |
| `safety_check`  | 有相关表达但意图不明           | 追问澄清，多轮状态机                  |
| `ocd_intrusive` | 侵入性思维（害怕自己会做某事） | 走 OCD 支持路径，**不误判为真实危机** |
| `none`          | 普通对话                       | 正常模型回复                          |

三条关键设计：

1. **侵入性思维不升级为危机**。强迫症患者常表达「我害怕自己会伤害家人」，这是强迫观念而非意图。系统需要区分「害怕会做」与「打算去做」。
2. **他人风险不标记本人**。用户说「朋友想自杀」时，风险对象是他人，不应把用户标记为危机。
3. **信息性上下文过滤**。讨论新闻、论文、影视作品时，不应触发危机流程。

### 8.2 情绪标签：三级瀑布

不额外增加模型调用：

1. **规则快通道**——第一人称锚定语法匹配明确情绪词，命中即用
2. **模型同次输出**——在生成回复的同一次响应里附带情绪字段（`response_format: json_object`）
3. **安全层覆盖**——危机场景强制覆盖为 `crisis`，模型无权决定

两条铁律：

- **危机判定权只在安全层**，模型永远不能输出 `crisis` 标签
- **情绪只反映发消息者本人**。用户描述他人情绪时，模型标签被丢弃

### 8.3 OCD 路由：亚型 + 共病 + 优先级

- **十类亚型**：污染、伤害、性、宗教/道德、关系、对称/秩序、躯体、魔法思维、囤积、混合
- **八类共病信号**：抑郁、焦虑、睡眠、进食、物质使用、注意、创伤、抽动
- **五级优先级**：P0 安全 > P1 强迫急性发作 > P2 OCD 科普计划 > P3 共病情绪 > P4 一般支持
- **双主轴标记**：P1 与 P3 同时出现时标记 `dual=true`，要求两个方向都回应，防止「只处理强迫、漏掉抑郁」

## 十、合规与免责

**这不是医疗器械，也不是医疗服务。**

- 所有自评结果仅供自我了解，**不构成诊断**，不能替代精神科或心理科评估
- 不提供用药建议，不做疗效承诺
- 危机情况下请立即联系专业机构（中国大陆可拨 12356 心理援助热线）

**部署者需自行确认**：向公众提供生成式 AI 服务时，需遵守《生成式人工智能服务管理暂行办法》《人工智能生成合成内容标识办法》等法规，涉及拟人化互动时，还应核对《人工智能拟人化互动服务管理暂行办法》等相关规范的有效版本、施行时间与适用性，并满足微信小程序对 AI 类目（深度合成-AI 问答）的资质要求。本项目不代办任何备案，也不构成合规建议。

界面上已内置「回复由人工智能生成，仅供陪伴与参考」的固定提示。二次开发时请勿移除，并建议进一步补充每条回复的标识。显式提示不等于已完成隐式标识或全部合规要求；部署者还需完善自己的运营主体、联系方式、隐私政策和必要备案信息。
